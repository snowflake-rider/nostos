# NOSTOS v2 구현 계약

[공통 라이브러리](README.md) · [전체 흐름](../../docs/architecture/shared-data/README.md) · [한 번에 테스트](../../tests/message-protocol/README.md)

2026-08-29: 통합 설계의 제안을 공통 C 코드로 구현했습니다. 이 파일은 **실제 구현된 바이트/실패 정책**의 기준이며 이전 brainstorm의 미정 표보다 우선합니다. 기본 배포 앱의 v1 경로를 자동 교체했다는 뜻은 아닙니다.

상태표는 `endpoint.receiver.shared_data`입니다. 정수·품질·수신 시각을 저장합니다. struct 전체를 전송하지 않으며 모든 여러 바이트 정수는 명시적 Little-endian입니다. 실패한 encode/decode는 caller의 출력 버퍼/길이/구조체를 보존합니다.

Hexdump는 Redpill Day14의 offset·hex·ASCII 표현을 공통 코드에 맞게 고정 버퍼와 출력 callback으로 적용했습니다. encode/decode가 자동 호출하지 않으며 ISR이나 메시지 전송 UART에서 사용하지 않습니다. 테스트 또는 별도 디버그 로그가 명시적으로 호출해야만 출력됩니다.

메시지 등록표는 Redpill Day11의 enum·함수 포인터 표 개념을 적용해 type마다 payload encode/decode 함수를 함께 보관합니다. 새 type은 등록표와 전용 codec, golden fixture, 상태 적용 검사를 함께 추가합니다. 수신한 type을 배열 인덱스로 직접 사용하지 않고 등록표를 검색하므로 `0x10`, `0x41`, `0x51`처럼 번호 사이가 비어 있어도 안전합니다.

## 공통 본문

```text
version:u8=2 | type:u8 | source:u8=1..3 | session:u32LE | sequence:u16LE | payload
    1            1          1                 4                2          가변
```

헤더9B, 전체9~64B입니다. 길이는 UART 프레임 또는 Mesh API에서 얻습니다. session0은 금지합니다. TTL·Mesh 암호화·분할/재조립은 ESP-IDF 책임이고 공통 본문에 중복하지 않습니다.

TTL은 초 단위 유효시간이 아니라 중계 횟수 제한입니다. 애플리케이션은 초기 TTL과 Relay 설정을 정하고, 감소·중계 중단은 Mesh 스택이 처리합니다. 현재 송신 설정은 TTL7입니다. `shared_data`에는 TTL을 저장하지 않으며, 센서값의 최신성이나 같은 사건의 중복 적용은 별도로 판단합니다. Mesh 수신 callback에서 다시 송신 API를 호출해 중계를 흉내 내지 않습니다.

| type | 메시지 | payload 순서 | 전체 크기 |
| --- | --- | --- | --- |
| `10/11/12/13` | 감속/가속/안전·응원/정지 | 없음 | 9B |
| `20/21/22` | 후방 안전/경고/미확인 | 없음 | 9B |
| `30/31` | FALL/SOS | incident_session:u32LE, incident_id:u16LE | 15B |
| `40` | 속도 | valid:u8, kmh_x10:u16LE | 12B |
| `41` | 온습도 | temperature_code:u8, humidity_code:u8 | 11B |
| `42/43` | FALL_CLEAR/SOS_CLEAR | incident_session:u32LE, incident_id:u16LE | 15B |
| `50` | heartbeat | status:u8 | 10B |
| `51` | ACK | acknowledged_source:u8, session:u32LE, sequence:u16LE, type:u8, result:u8 | 18B |

숫자는 16진수 type입니다. 기존12종 설계에 후방 미확인, SOS 해제, 의미가 정의된 ACK를 추가해 15종입니다. `REAR_UNKNOWN`은 미수신과도 구분되는 명시적 센서/관찰 실패입니다. 속도 valid는0/1만, invalid일 때 wire 값은0만 허용하며 실제 0km/h와 구분합니다. 정상 속도 범위는0~6553.5km/h의 표현 범위이며 센서별 물리 타당성 검사는 생산자 책임입니다.

**역할/기능:** source와 role은1~3의 사전 등록표로 연결합니다. ESP32는 서로 다른 세 source·role·실제 Mesh 주소를 검증합니다. capabilities는 전송하지 않습니다. 물리 센서의 역할별 허용 목록은 아직 배포 설정이 필요하며, 이 구현이 임의의 새 센서 배정을 하거나 기존 STM32 센서 기본값을 끄지는 않습니다.

### 온습도2B

- 온도225~475(°C×10): `code=t_x10-225`, 복원 `t_x10=code+225`.
- 습도0~1000(%×10): `code=(h_x10+2)/5`, 복원 `h_x10=code*5`.
- 코드251=범위 미만,252=범위 초과,253=센서 오류,254=미측정.255와 습도201~250은 거부합니다.
- 정상 입력이 표현 범위 밖이면 정상 경계값으로 clamp하지 않고 범위 오류 코드를 보냅니다. 오류 상태에서 이전 정상값은 보존하되 품질/정상값 시각을 새 측정처럼 바꾸지 않습니다.

```text
36.2°C, 60.3%, source2, session1, seq7
02 41 02 01 00 00 00 07 00 89 79
수신: 362, 605 → 36.2°C, 60.5%
```

### heartbeat1B / ACK

status bit0=센서 오류, bit1=출력 오류, bit2=입력 큐 overflow 관찰. bit3~7은0이어야 합니다. 이는 장착 기능이 아니라 현재 건강 보고이며, heartbeat가 없으면0을 정상으로 간주하지 않습니다. 발생/해제 시점은 실제 생산자가 관리합니다. 더 세밀한 상태는 새 type을 추가합니다.

ACK result0=응용 수락/요청 큐에 들어감,1=중복,2=미지원,3=거부입니다. ACK 자신에게 ACK하지 않습니다. 성공/중복 응답은 등록된 type만 참조할 수 있습니다. **ACK encoder/decoder/수신 목적지 검사는 구현했지만 자동 ACK 생성·미응답 재전송·미결 요청과의 매칭은 구현하지 않았습니다.** 수신 API 성공이나 ACK 수신을 스피커 재생 완료·신뢰성 보장으로 해석하지 않습니다. 응용이 이 기능을 쓸 때 참조 source/session/sequence/type 전체를 자신이 보낸 미결 요청과 대조해야 합니다.

## UART 외부 프레임

```text
7E | escaped( body_length:u8 | common_body | CRC16:u16LE ) | 7E
```

- `7E`와 `7D`는 `7D` 뒤에 원래 값 XOR`20`으로 escape합니다. 다른 escape 조합은 거부합니다.
- CRC-16/CCITT-FALSE: poly`1021`, init`FFFF`, refin=false, refout=false, xorout`0000`. 검사 범위는 **unescaped 길이1B+공통 본문**. 기준값 `123456789 → 29B1`.
- 위 온습도 예제의 전체 UART golden: `7E 0B 02 41 02 01 00 00 00 07 00 89 79 05 B9 7E` (16B). Python `binascii.crc_hqx`로 CRC를 독립 대조했습니다.
- 전체 wire 본문 최대64B, UART 최악 프레임 최대136B. parser는 고정 버퍼만 사용합니다.
- 진행 중 프레임에서 바이트 간격이100ms를 초과하면 버립니다. 다음 경계에서 다시 시작합니다. 길이 초과/CRC/escape 오류도 다음 경계까지 버립니다.
- UART CRC는 우연한 전송 오류 검출이지 인증이 아닙니다. 원격 source 인증 경계는 ESP32의 Mesh 출처 매핑입니다. 모든 구성원이 같은 AppKey를 아는 프로토타입의 악의적 구성원까지 방어하는 서명 체계는 아닙니다.

## 수신·상태·사건 규칙

1. `decode`가 버전/종류/정확한 길이/값을 검사합니다. 미지원 type/version을 손상과 구분합니다.
2. ESP32는 Mesh의 **원 발신 주소**와 payload source를 등록표로 대조합니다. relay의 주소로 바꾸지 않습니다. 같은v2의 모르는 type은64B 이내에서 원본 그대로 운반할 수 있지만, STM32는 건너뛰고 성공 ACK/출력을 만들지 않습니다. 알려진 type의 잘못된 길이는 거부합니다.
3. STM32는 `nostos_receiver_approve_session()`으로 **신뢰된 설정 경로에서 승인한 세션**만 받습니다. 메시지가 자기 session을 승인하지 못합니다. 세션은 증가해야 하고 자동 wrap하지 않습니다.
4. 각 source에서64개 순번 수신 창으로 중복을 거부합니다. 최신성은 환경/속도/후방/heartbeat별로 비교하므로 다른 종류의 지연 메시지까지 잘못 버리지 않습니다. 창 밖의 지연 메시지는 거부합니다. 송신 순번65535 다음은`EXHAUSTED`입니다.
5. FALL/SOS는 source+종류+사건세션+사건번호로 구분합니다. 사건 생성세션/번호는0 금지. 새 발생은 현재 메시지 세션에서 만들고, CLEAR는 자신 소유의 과거/현재 사건만 종료합니다. 재발은 새 사건번호입니다. CLEAR 선도착을 종료기록으로 저장하고 뒤늦은 발생의 부활을 막습니다.
6. 종료기록/활성 사건은24개 고정 슬롯입니다. 자동 만료/eviction하지 않습니다. 가득 차면`FULL`을 반환하고 기존 사건을 지우지 않습니다. 세션 변경·연결 끊김·시간초과로 낙상/SOS를 자동 해제하지 않습니다.
7. 음소거는 이 수신기의 정확한 사건 한 건에만 적용하며 공유 상태를 해제하지 않습니다. 다른 사건은 계속 소리를 낼 수 있습니다.
8. 센서 보고의 수신 시각과 정상값 시각을 구분합니다. heartbeat/중복/오류 보고로 정상 센서값의 나이를 연장하지 않습니다. freshness 기본3초는 로컬 관찰 기준이며 실제 측정 시각의 증명은 아닙니다.

**재부팅 경계:** 현재 라이브러리는 RAM 상태와 승인/복구 API입니다. STM32 Flash/NVS 저장 장치를 구현하지 않았습니다. 수신기 재부팅 후 세션·순번 floor·활성/종료 기록의 신뢰된 복구 없이 과거 세션을 재승인하면 과거 명령이 살아날 수 있습니다. 영속 저장 또는 새 세션 재합의가 준비될 때까지 새 펌웨어의 자동 배포를 하지 않습니다. 테스트는 미승인/이전 세션 거부·floor·사건 보존을 검사하며 Flash 복구를 검사한 것이 아닙니다.

## 출력과 큐

- ESP32 bridge: 전체16개 작업 중 일반 메시지는 최대12개이고4개는 FALL/SOS/FALL_CLEAR/SOS_CLEAR용으로 예약합니다. 긴급 메시지를 일반 메시지보다 먼저 꺼내되, 긴급4개를 연속 처리한 뒤 기다리는 일반 메시지1개를 처리해 영구 굶김을 막습니다. 긴급끼리와 일반끼리는 각각 수신 순서를 유지합니다. 긴급 메시지만16개가 차면 추가 긴급 메시지도`FULL`입니다. 최대 대기2초이며 송신 실패/부분 UART 전송을 자동 재시도하지 않습니다. UART writer는 하나이고 Mesh callback 안에서 UART를 기다리지 않습니다.
- STM32 버튼 요청:8개 큐. 처리 시 오디오가 비어 있으면 한 건씩 재생하고2초가 넘으면 만료시킵니다. 중복으로 재생하지 않습니다.
- 낙상/SOS는 빨간 점멸/긴급 부저 우선입니다. 모든 활성 사건이 로컬 음소거되면 빨간 표시를 유지하고 부저만 끕니다.
- 긴급 사건이 없을 때 신선한 후방 경고는 노란 점멸/후방 부저, 신선한 안전 보고가 있으면 녹색, 나머지는 OFF입니다. 녹색은 **수신한 안전 보고의 표시**이지 모든 라이더/도로의 안전 보장이 아닙니다.
- RGB/부저는 실제 GPIO 드라이버를 사용합니다. 네 가지 버튼 음성은 로컬 MP3→VS1003B SPI 경로입니다. FALL/SOS 전용 MP3는 없으므로 부저로 알립니다.
- rear warning MP3 자산은 기존 코드에 있지만 v2 endpoint의 자동 음성 큐는 현재 버튼4종입니다. 재생 중 음성을 강제로 끊는 하드웨어 codec 취소/선점은 구현하지 않았습니다.
- STM32 `message_protocol_service_stats()`로 적용/중복/거부/overflow와 최근 결과를 읽습니다. 사건 슬롯 FULL을 포함한 오류는 성공으로 기록하지 않습니다.

호스트 ABI에서 receiver1280B/endpoint1448B였습니다. 타깃 ABI 크기와 ISR/RTOS stack 최대치는 타깃 빌드/실물 측정 대상입니다. 동적 메모리 할당을 하지 않습니다. bridge는 caller가 lock을 소유하며 STM32 endpoint는 메인 루프 한 곳에서 호출합니다.

## 펌웨어 연결과 배포 경계

### ESP32

[bridge_runtime_v2.c](../../firmware/esp32/main/bridge_runtime_v2.c)는 `CONFIG_NOSTOS_PROTOCOL_V2=y`일 때 기존 runtime 대신 빌드됩니다. 기본은v1입니다. source1/2/3의 **실제 provisioned Mesh 주소**와 로컬source를 [Kconfig.projbuild](../../firmware/esp32/main/Kconfig.projbuild)에 설정해야 합니다. 주소0·중복이면 시작 실패, 자기 실제 주소가 설정과 다르면 송수신을 거부합니다. 테스트의`0101/0202/0303`은 mock주소이며 실제 장치에 복사하지 않습니다.

v2 Vendor opcode는`ESP_BLE_MESH_MODEL_OP_3(0x21, 0x02E5)`입니다. 기존v1의`0x20`과 구분하며 prototype company/model/group은 그대로 둡니다. company ID는 기존 Espressif 예제 기반의 폐쇄 프로토타입용입니다. UART1 TX17/RX18/115200/8N1, Mesh TTL7과 기존 SDK 분할 설정을 유지합니다. Mesh 수신을 응용에서 재방송하지 않습니다.

### STM32

[message_protocol_service.c](../../firmware/stm32/MyApp/service/message_protocol_service.c)는 새 endpoint를 실제 RGB/부저/audio 드라이버에 연결합니다. CMake `-DNOSTOS_PROTOCOL_V2=ON`이면 `app.c`/`message_router.c`/`uart_service.c`도 새 경로를 선택합니다. 기본은v1입니다.

- 실제 HAL RX callback은 바이트/수신시각을512칸 ring에 넣고 재수신만 시작합니다. 메인 루프가 최대64바이트씩 decode/apply합니다. overflow/하드웨어 오류에서 partial frame과 ring을 폐기하고 다음 정상 프레임으로 복구합니다.
- `app_init()`이 `message_protocol_service_boot()`를 호출합니다. **기본 weak hook은 NOT_READY로 실패합니다.** 배포 코드가 이를 override해 승인된 로컬source/session, 상대 세션/floor, 활성·종료 기록을 복구해야 합니다. 고정된 가짜 session을 자동 사용하지 않습니다. 디버거의 `protocol_debug_boot_status`에서 상태를 확인합니다.
- 올바른 boot provider는 기존 VS1003B 초기화 결과로 `message_protocol_service_init()`을 호출한 뒤 신뢰된 상태를 복구합니다. 패킷 안의 source/session으로 자동 승인하지 않습니다.
- 기존 버튼/안전 이벤트는 v2 router가 메시지로 만들며, 새 사건번호는 소진 시 실패합니다. `nostos_endpoint_publish()`로 속도/온습도/heartbeat 같은 생산자도 연결할 수 있습니다. 수신 raw1byte 디버거 주입으로 출처 검증을 우회하지 않습니다.
- v2 안전 서비스는 초음파 연속 무응답을100cm/SAFE로 바꾸지 않고 REAR_UNKNOWN으로 보고합니다. 기존v1 동작과 센서 활성 기본값은 보존합니다.

따라서 **UART ISR→메인 루프→decode/apply→출력의 코드 경로는 연결됐지만**, 실제 보드의 영속 boot provider, DHT11·OLED·속도 생산자 이식과 실물 배포는 별도 작업입니다. 2026-08-29에 `bash tests/message-protocol/run.sh --all`로 호스트 회귀 및 v2 ON STM32 Debug/Release·ESP32-S3 전체 빌드를 통과했습니다. STM32는 기본 boot hook이 실패해도 공개 init과 codec·출력 경로가 ELF에서 제거되지 않도록 링크하며, boot 승인 조건 자체는 완화하지 않습니다. 보드 Flash/설정을 변경하지 않았습니다. 빌드와 호스트 HAL 테스트는 부팅 저장장치·실제 RTOS·전파 검증이 아닙니다. [실행 옵션과 검증 기록](../../tests/message-protocol/README.md).

## 새 데이터 추가

등록표에 새type·고정 길이·단위·오류 규칙을 추가하고 codec/state 처리와 golden fixture를 함께 추가합니다. 기존 `(version,type)`의 의미/길이를 바꾸지 않습니다. 헤더 의미가 바뀌면 새version입니다. unknown v2 payload 안의`13`이나`7E`도 일회성 요청으로 실행하지 않습니다. 배터리/GPS는 아직 등록하지 않은 확장 예시입니다.
