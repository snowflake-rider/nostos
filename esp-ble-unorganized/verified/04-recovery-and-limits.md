# 04. 복구 확인과 아직 남은 문제

검증일: 2026-08-28 (KST). 성공한 정상 동작과 해결되지 않은 reset 문제를 구분한다.

## 원래 STM32 상태 복구

UART 단독 시험에만 임시 10회 주기 송신 이미지를 사용했다. 성공 시험 후에는 다음을 확인했다.

- 시험 직전 읽은 STM32 전체 Flash 512KB가 이전 원본 백업과 일치했다.
- 그 이미지를 다시 설치하여 전체 download verify와 reset이 성공했다.
- `Core/Src/main.c`와 일반 Debug ELF는 시험 전 파일과 바이트 단위로 일치했다.
- 새 프로젝트·IOC 생성이나 PA10 버튼 전환을 하지 않았다. 버튼은 기존 D10/PB6였다.
- 이어진 버튼→Mesh 시험은 복구된 원래 STM32 펌웨어에서 수행했다.
- ESP32에는 새 펌웨어나 Mesh 키·그룹 설정을 쓰지 않았다. UART 단독 진단 중 D6 재부팅만 수행했다.

복구 로그의 확인 문구:

```text
Size          : 512.00 KB
Download verified successfully
Software reset is performed
```

Flash 백업에는 사용자 데이터가 포함될 수 있으므로 이 문서 디렉터리로 복사하지 않았다. 복구 로그의 위치와 해시는 [증거 문서](05-evidence.md)에 남겼다.

## 관찰된 문제와 경과

| 시점 | 실제 관찰 | 판정 |
| --- | --- | --- |
| 초기 배선·GND 이동 후 | STM32 송신 10회, D6 수신 0회; D6 GPIO18 LOW | UART 전달 실패 |
| 사진 확인 후 GPIO11→18 이동 | GPIO18 HIGH로 바뀌었지만 첫 실행 수신 0회; 버퍼 240바이트 정체 | 핀 수정만으로 수신 회복 미확인 |
| D6 재부팅 후 UART 재시험 | 정상 `0x13` 구간 10/10 수신 | UART 정상 동작 확인 |
| STM32 reset 직후 | 다른 유효 ID·noop·invalid 입력 | reset 구간의 잡음 관찰, 원인 미확정 |
| 원래 STM32 Flash 복구/reset 후 | D6 버퍼 240바이트 정체 재관찰 | reset 관련 안정성 문제 남음 |
| STM32를 그대로 두고 D6만 재부팅 | 버퍼 0, GPIO18 HIGH, 기존 Mesh 설정 유지 | 일시적인 상태 회복 확인 |
| 뒤이은 실제 버튼 시험 | 3회 모두 D6 UART·76 Mesh 수신, UART 오류 0 | 해당 관찰 구간 3/3 성공 |

**D6 재부팅은 이번에 관찰된 임시 회복 방법이지 근본 수정이 아니다.** 잘못된 핀 연결과 reset 시 수신 정체는 분리해서 기록한다. 사진·디지털 레벨·로그만으로 정체의 전기적/드라이버 원인을 단정하지 않는다.

## 이번에 검증하지 않은 항목

- STM32 reset·Flash 직후에도 UART가 자동 회복하는지.
- 전원 투입 순서, 반복 reset, 장시간 안정성, 대량·고속 메시지 처리.
- 세 번째 보드 B6의 동시 수신 및 제어된 다중 홉 Relay.
- ESP32→STM32 역방향 UART의 실제 전달.
- 메시지를 받은 뒤 LED·버저·오디오·센서 기능이 기대대로 동작하는지.
- PA10을 버튼 입력으로 바꾼 구성. 이번에는 PA10 USART1 RX를 유지했다.
- 거리·장애물·전파 간섭 조건별 수신 성능, 응용 계층 ACK/재전송 보장.

## 다음 재시험의 기준

후속 작업을 한다면 변경 전후의 source·ID·송신 횟수·수신 횟수를 함께 기록한다. reset 문제를 조사할 때는 reset 전후 `buffered`, `valid/noop/invalid/hw_errors`, GPIO18 레벨을 분리해서 수집한다. `MESH_TX accepted`만으로 성공 처리하거나 배경 Mesh 데이터를 목표 메시지로 세지 않는다.

이 항목들은 후속 검증 기준이며, 이번 문서 작성에서 실행하거나 수정하지 않았다.
