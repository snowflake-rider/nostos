# NOSTOS v2 프로토콜

## 한눈에 보기

NOSTOS v2는 두 가지 형식을 사용합니다.

| 구분 | 로컬 UART 패킷 | 공식 NOSTOS 메시지 |
| --- | --- | --- |
| 구간 | STM32 ↔ paired ESP32 | ESP32 ↔ ESP32 Mesh |
| 역할 | 센서 입력과 출력 명령 전달 | 노드 간 이벤트와 상태 공유 |
| 식별값 | 없음 | source, session, sequence |
| 오류 검출 | CRC-16 | BLE Mesh가 처리 |

```text
STM32 센서·버튼
  -> 로컬 UART 패킷(A5 5A, CRC)
  -> paired ESP32
  -> 공식 메시지(source/session/sequence)
  -> BLE Mesh
```

STM32는 센서·버튼을 읽고 OLED·RGB·audio를 실행합니다. ESP32만 공식 메시지를 만들고 상태, 중복 제거, 출력 순서를 관리합니다.

## 1. 공식 NOSTOS 메시지

```text
version:u8=2 | type:u8 | source:u8 | session:u32LE | sequence:u16LE | payload
```

헤더는 9B, 전체는 9~64B입니다. 여러 바이트 정수는 Little-endian입니다.

| 필드 | 의미 |
| --- | --- |
| version | 프로토콜 버전. 항상 `2` |
| type | 메시지 종류 |
| source | 발신 노드 번호 `1..3` |
| session | ESP32 부팅 세대. `0` 금지 |
| sequence | 같은 session 안의 메시지 순서 |
| payload | type별 실제 데이터 |

예: source 1, session `0x12345678`, sequence 5의 SPEED_UP

```text
02 | 11 | 01 | 78 56 34 12 | 05 00
```

### 메시지 종류

| type | 이름 | payload | 전체 |
| --- | --- | --- | ---: |
| `10` | SPEED_DOWN | 없음 | 9B |
| `11` | SPEED_UP | 없음 | 9B |
| `13` | STOP | 없음 | 9B |
| `30` | FALL | incident_session:u32LE, incident_id:u16LE | 15B |
| `41` | ENVIRONMENT | temperature_code:u8, humidity_code:u8 | 11B |
| `42` | FALL_CLEAR | incident_session:u32LE, incident_id:u16LE | 15B |
| `44` | RIDE | valid:u8, kmh_x10:u16LE, distance_mm:u32LE | 16B |
| `46` | SHARED_DATA_REQUEST | mask:u8 | 10B |
| `50` | HEARTBEAT | status:u8 | 10B |
| `51` | ACK | source, session, sequence, type, result | 18B |

값 규칙:

- RIDE `valid=0`이면 속도와 거리는 모두 0입니다.
- ENVIRONMENT 특수 code `251..254`는 범위 미만, 범위 초과, 센서 오류, 미측정입니다.
- FALL의 incident session/id는 0일 수 없습니다.
- SHARED_DATA_REQUEST bit0은 RIDE, bit1은 ENVIRONMENT입니다.
- ACK는 메시지 수락 여부이며 실제 출력 완료나 전달 보장이 아닙니다.
- 등록되지 않은 type과 잘못된 길이·값은 거부합니다.

### 공식 UART framing

공식 메시지를 UART로 보낼 때 쓰는 형식입니다. 현재 STM32↔ESP32 runtime은 이 형식 대신 아래 로컬 패킷을 사용합니다.

```text
7E | escaped(length:u8 | official_message | CRC16:u16LE) | 7E
```

CRC-16/CCITT-FALSE는 poly `1021`, init `FFFF`이며 `길이 + 공식 메시지`를 검사합니다. `7E/7D`는 escape합니다. 100ms timeout이나 길이·escape·CRC 오류가 발생하면 다음 `7E`까지 버립니다. CRC는 인증이나 암호화가 아닙니다.

## 2. STM32 ↔ ESP32 로컬 UART 패킷

```text
A5 5A | version=01 | type:u8 | length:u8 | payload | CRC16:u16LE
```

이 형식은 UART1 전용이며 Mesh payload가 아닙니다. 공식 source/session/sequence도 없습니다. paired ESP32가 로컬 값을 받은 뒤 해당 정보를 붙입니다.

예: STM32의 BUTTON1 / SPEED_UP

```text
A5 5A | 01 | 07 | 01 | 11 | C5 46
시작값  버전  EVENT 길이  값   CRC
```

CRC 범위는 `version + type + length + payload`입니다. 시작값 `A5 5A`는 포함하지 않습니다.

| 방향 | type | 내용 | 전체 |
| --- | --- | --- | ---: |
| STM→ESP | `02` | HELLO | 7B |
| STM→ESP | `06` | RIDE | 14B |
| STM→ESP | `07` | EVENT | 8B |
| STM→ESP | `08` | ENVIRONMENT | 13B |
| STM→ESP | `09` | SHARED_DATA_REQUEST | 8B |
| ESP→STM | `0A` | READY | 11B |
| ESP→STM | `0B` | OUTPUT_EVENT | 13B |
| ESP→STM | `0C` | OUTPUT_RIDE | 19B |
| ESP→STM | `0D` | OUTPUT_ENVIRONMENT | 18B |
| STM→ESP | `0E` | OUTPUT_RESULT | 12B |

100ms timeout, 길이·CRC·값 오류가 발생하면 패킷을 버리고 다음 `A5 5A`에서 다시 시작합니다. 기존 type `03..05`는 이전 이미지 decode 호환용이며 현재 runtime은 사용하지 않습니다.

## 3. 메시지 식별과 중복 제거

- `source`: provisioned Mesh primary 주소에 연결된 노드 번호입니다.
- `session`: ESP32가 부팅할 때 NVS에서 증가·저장합니다. 저장 실패 시 송신하지 않습니다.
- `sequence`: session마다 0부터 증가합니다. 65535 다음에는 wrap하지 않습니다.
- 수신 ESP32는 Mesh 주소와 source가 일치하는지 확인합니다.
- source별 최근 64개 sequence로 중복과 오래된 메시지를 거부합니다.
- 더 높은 session을 받으면 그 source의 이전 상태와 대기 출력을 비웁니다.

STM32는 공식 source/session/sequence를 저장하거나 처리하지 않습니다.

## 4. 상태와 출력

- ESP32는 source 1~3의 RIDE, ENVIRONMENT, FALL 최신 상태를 RAM에 저장합니다.
- 센서값 유효 시간은 3000ms입니다. RIDE/ENVIRONMENT는 이력 큐 대신 6칸 latest-value slot을 사용합니다.
- FALL은 `source + incident session + incident id`로 구분하며 최대 24개를 저장합니다.
- 이벤트 출력은 16칸 고정 큐를 사용합니다.

```text
P1 FALL/FALL_CLEAR > P2 STOP > P3 SPEED_DOWN > P4 SPEED_UP
```

P1용 4칸, P2용 1칸을 예약합니다. 같은 우선순위는 FIFO입니다. P2~P4는 2000ms 후 폐기하며 P1은 만료하지 않습니다.

## 5. 부팅과 출력 명령

```text
ESP32 NVS session 증가
  -> READY(command_epoch=session)
  -> STM32 센서 송신과 OUTPUT 실행 시작
```

- STM32는 READY 전까지 1초마다 HELLO를 보냅니다.
- command_id는 epoch마다 1부터 증가합니다.
- STM32는 이미 처리한 command_id를 재실행하지 않고 DUPLICATE를 반환합니다.
- OUTPUT_RESULT는 accepted/duplicate/rejected/hardware-error 중 하나입니다.
- UART 성공과 실제 OLED·RGB·audio 성공은 별개입니다.

## 6. 활성화와 검사

```text
ESP32: CONFIG_NOSTOS_PROTOCOL_V2=y
STM32: -DNOSTOS_PROTOCOL_V2=ON
UART1: TX17/RX18, 115200/8N1
Mesh:  vendor opcode 0x21/0x02E5, TTL 7
```

주소가 0이거나 중복·불일치하면 송수신을 거부합니다. READY 전에는 v1 fallback이나 자동 Flash를 하지 않습니다. BTN4는 로컬 reset/mute 전용이며 UART나 Mesh로 보내지 않습니다.

새 type은 등록표, 고정 길이, codec, 상태 처리, golden fixture를 함께 추가합니다. 기존 `(version,type)`의 의미나 길이를 바꾸지 말고 헤더가 바뀌면 새 version을 사용합니다.

```sh
bash firmware/tools/fw check protocol
bash firmware/tools/fw test protocol
```

실제 배포 전에는 ESP32·STM32 target build와 실물 통신 검증도 필요합니다.
