# NOSTOS v2 구현 계약

v2는 양쪽 펌웨어의 기본 개발 프로토콜입니다. 공식 packet 생성·검증, source/session/sequence,
중복 제거, 공유 상태와 출력 task scheduling은 ESP32 한 곳만 소유합니다. STM32는 paired UART의
sensor/button producer와 화면·RGB·audio actuator만 담당합니다. ESP32가 실제 provisioned primary 주소를
등록된 source에 연결하지 못하거나 NVS boot session을 commit하지 못하면 fail-closed로 송수신을
거부합니다. 배포에는 새 bundle release와 실물 검증이 필요합니다.

## 공통 본문

```text
version:u8=2 | type:u8 | source:u8 | session:u32LE | sequence:u16LE | payload
```

헤더는 9B, 전체는 9~64B입니다. source는 1~3, session은 0이 아니어야 하며 모든 여러 바이트 정수는
Little-endian입니다. 길이는 외부 UART 프레임 또는 Mesh API가 제공합니다. encode/decode 오류 시 caller의
출력 버퍼·길이·구조체를 변경하지 않습니다.

| type | payload | 전체 |
| --- | --- | ---: |
| `10` BUTTON2/SPEED_DOWN | 없음 | 9B |
| `11` BUTTON1/SPEED_UP | 없음 | 9B |
| `13` BUTTON3/STOP | 없음 | 9B |
| `30` FALL | incident_session:u32LE, incident_id:u16LE | 15B |
| `41` ENVIRONMENT | temperature_code:u8, humidity_code:u8 | 11B |
| `42` FALL_CLEAR | incident_session:u32LE, incident_id:u16LE | 15B |
| `44` RIDE | valid:u8, kmh_x10:u16LE, distance_mm:u32LE | 16B |
| `46` SHARED_DATA_REQUEST | mask:u8 (`bit0=RIDE`, `bit1=ENVIRONMENT`) | 10B |
| `50` HEARTBEAT | status:u8 | 10B |
| `51` ACK | acknowledged_source:u8, session:u32LE, sequence:u16LE, type:u8, result:u8 | 18B |

- application 공유 항목은 주행 속도·누적 바퀴 이동거리, 온도·습도, 버튼 1/2/3, 낙상 발생·해제뿐입니다.
  HEARTBEAT와 ACK는 내부 상태/제어용입니다. 등록표에 없는 type은 bridge가 전달하지 않습니다.
- incident session/id는 모두 0 금지입니다. RIDE valid는 0/1이며 invalid이면 kmh_x10과 distance_mm가
  모두 0이어야 합니다. distance_mm는 바퀴 회전으로 누적한 주행거리입니다.
- 온도 정상 code `0..250`은 `°C×10=code+225`, 습도 정상 code `0..200`은 `%×10=code×5`입니다.
  `251/252/253/254`는 범위 미만/초과/센서 오류/미측정이며 `255`와 습도 `201..250`은 거부합니다.
- HEARTBEAT bit0/1/2는 sensor/output/input-overflow 오류이고 상위 bit는 0이어야 합니다.
- 공식 SHARED_DATA_REQUEST mask는 0이 아니어야 하며 `RIDE|ENVIRONMENT` 이외 bit를 거부합니다.
  현재 paired UART 조회는 공식 packet을 만들지 않고 아래 `SENSOR_LINK_SHARED_DATA_REQUEST`를 사용합니다.
  ESP32는 어느 형태의 snapshot 요청도 Mesh로 재전송하지 않습니다.
- ACK result `0/1/2/3`은 applied-or-queued/duplicate/unsupported/rejected입니다. ACK에 ACK하지 않으며
  자동 ACK·재전송·미결 요청 매칭은 구현하지 않았습니다. ACK는 출력 완료나 전달 보장이 아닙니다.

## UART 프레임

```text
7E | escaped(body_length:u8 | common_body | CRC16:u16LE) | 7E
```

`7E/7D`는 `7D` 뒤에 원래 값 XOR `20`으로 escape합니다. CRC-16/CCITT-FALSE는 poly `1021`, init
`FFFF`, refin/refout false, xorout `0000`이며 unescaped 길이+본문을 검사합니다(`123456789 → 29B1`).
본문 최대 64B, 최악 프레임 136B이고 고정 버퍼만 사용합니다. 바이트 간격이 100ms를 초과하거나
길이·escape·CRC가 틀리면 다음 `7E`까지 버립니다. CRC는 인증이 아닙니다.

### Paired STM32/ESP32 로컬 프레임

STM32의 센서·버튼·FALL 측정과 로컬 조회 명령은 먼저 paired ESP32에 이 envelope로 전달됩니다.
ESP32에 직접 연결된 XOSS 값도 같은 producer 구조체를 사용하지만 UART 왕복은 하지 않습니다. 이
프레임에는 공식 source/session/sequence가 없고 UART1에서만 쓰며 Mesh payload가 아닙니다.

```text
A5 5A | version=01 | type:u8 | length:u8 | payload | CRC16:u16LE
```

| 방향 | type | payload | 전체 |
| --- | --- | --- | ---: |
| STM→ESP | `02` HELLO | 없음 | 7B |
| STM→ESP | `06` RIDE | valid:u8, kmh_x10:u16LE, distance_mm:u32LE | 14B |
| STM→ESP | `07` EVENT | event type:u8 | 8B |
| STM→ESP | `08` ENVIRONMENT | temperature_c_x10:i16LE, humidity_pct_x10:u16LE, temperature_quality:u8, humidity_quality:u8 | 13B |
| STM→ESP | `09` SHARED_DATA_REQUEST | mask:u8 (`bit0=RIDE`, `bit1=ENVIRONMENT`) | 8B |
| ESP→STM | `0A` READY | command_epoch:u32LE | 11B |
| ESP→STM | `0B` OUTPUT_EVENT | command_id:u32LE, source_id:u8, event type:u8 | 13B |
| ESP→STM | `0C` OUTPUT_RIDE | command_id:u32LE, source_id:u8, valid:u8, kmh_x10:u16LE, distance_mm:u32LE | 19B |
| ESP→STM | `0D` OUTPUT_ENVIRONMENT | command_id:u32LE, source_id:u8, temperature_c_x10:i16LE, humidity_pct_x10:u16LE, temperature_quality:u8, humidity_quality:u8 | 18B |
| STM→ESP | `0E` OUTPUT_RESULT | command_id:u32LE, status:u8 | 12B |

CRC-16/CCITT-FALSE는 `version`부터 payload까지 검사합니다. parser는 최대 19B 고정 버퍼로 length를
따라 수신하고 바이트 간격이 100ms를 초과하거나 길이·CRC·값이 틀리면 다음 preamble에서
재동기화합니다. command_epoch와 command_id는 0을 금지합니다. source_id는 1~3이고 RIDE valid가 0이면
속도와 누적거리가 모두 0이어야 합니다. EVENT는 BUTTON1/2/3, FALL, FALL_CLEAR만 허용하고 quality는
`UNMEASURED..SENSOR_ERROR`만 허용합니다. OUTPUT_RESULT status는 accepted/duplicate/rejected/
hardware-error입니다. 기존 `03`~`05` codec은 이전 이미지 호환용으로 남아 있지만 현재 runtime은
IDENTITY, APPROVE_SESSION, IDENTITY_ACK를 송수신하지 않습니다.

paired ESP32 한 곳만 공식 source/session/sequence와 FALL incident id를 붙입니다. STM32와 XOSS는
측정값 producer일 뿐 공식 packet writer가 아니므로 같은 센서값을 두 번 발행할 수 없습니다. STM32는
공식 `7E` frame을 parse하거나 만들지 않으며 ESP32의 OUTPUT 명령만 실행합니다.

```text
STM 센서/버튼/FALL -> local envelope -> paired ESP official writer/state
XOSS BLE ----------------------------> paired ESP official writer/state
                                       |-> fixed min-heap/latest slots -> OUTPUT_* -> STM actuator
                                       `-> Mesh -> 모든 ESP state -> 각 paired STM actuator
```

## 수신·상태·큐·출력 스케줄링 제약

- ESP32는 provisioned 원 발신 Mesh 주소와 payload source를 사전 등록된 1~3 매핑으로 검증합니다.
  등록표에 없는 type과 제거된 type은 `UNSUPPORTED_TYPE`으로 거부하고 큐에 넣지 않습니다.
- 원격 NOSTOS packet은 자신의 세션을 승인할 수 없습니다. ESP32가 검증한 Mesh 원 발신 주소와 본문
  source를 대조한 뒤 ESP32의 단일 receiver가 session 승인, replay window와 공식 상태를 처리합니다.
  STM32에는 공식 session이나 packet을 전달하지 않습니다. 더 높은 source session은 ESP32에서 그 source의
  `shared_data`, pending STOP/버튼, FALL 사건과 닫힌 tombstone을 비운 strict empty epoch를 시작합니다.
- source별 64순번 창이 중복·오래된 순번을 거부합니다. sequence 65535 다음은 `EXHAUSTED`이며 wrap하지 않습니다.
- FALL/FALL_CLEAR는 source+incident session/id로 식별합니다. 사건/tombstone은 고정 24칸이고
  같은 source session 안에서는 자동 만료·eviction하지 않습니다. CLEAR 선도착과 정확한 사건별 mute를
  보존하지만 더 높은 source session은 이전 epoch의 FALL/tombstone을 명시적으로 폐기합니다. 이는 source
  reset을 이전 process lifetime의 종료로 간주하는 제품 선택입니다. 따라서 reset 뒤 새 session이 승인되면
  이전 FALL은 별도 FALL_CLEAR 없이 끝나며, 재부팅 이후에도 위험이 계속되면 새 session에서 FALL을 다시
  감지·발행해야 합니다.
- RIDE와 ENVIRONMENT는 source별 독립 ordering을 적용하고 센서 freshness는 로컬 수신 기준 3000ms입니다.
  수락한 최신 센서값은 application `shared_data`의 해당 source 항목을 덮어쓰며 별도 이력 큐에 쌓지
  않습니다. invalid RIDE 보고는 마지막 정상 속도·누적거리와 그 시각을 덮지 않습니다.
- 각 ESP32의 receiver가 source 1~3별 RIDE/ENVIRONMENT와 FALL 상태를 고정 크기 RAM에 소유합니다.
  STM32 상태는 화면·출력용 mirror일 뿐입니다. 센서 출력 대기는 source×type의 6칸 latest-value slot을
  사용하며 동적 할당과 센서 backlog가 없습니다. STM32 `HELLO`에서는 활성 FALL과 fresh 센서 snapshot을
  ESP32가 다시 OUTPUT 명령으로 내보내고, ESP32 재부팅 때만 RAM 상태가 비어 시작합니다.
- 로컬 producer-consumer 경계는 동적 할당 없는 FreeRTOS static queue를 사용하고 공식 writer에는 worker
  하나만 접근합니다. STM32와 XOSS의 로컬 값, 인증된 Mesh 값은 모두 같은 application receiver를 거친 뒤
  출력 scheduler로 들어갑니다.
- 이벤트 출력 task scheduler는 16칸 고정 min-heap입니다. key는 `priority, arrival_order`이고
  `P1 FALL/FALL_CLEAR > P2 STOP > P3 BUTTON2/SPEED_DOWN > P4 BUTTON1/SPEED_UP`입니다. 같은 priority는
  안정적인 FIFO입니다. 4칸은 P1, 1칸은 P2 진입용으로 예약하여 일반 event가 안전 task를 막지 못합니다.
  P2~P4는 2000ms가 지나면 폐기하고 P1은 시간 만료하지 않습니다. RIDE/ENVIRONMENT는 heap에 넣지 않습니다.
- 다중 source FALL 출력은 ESP32의 전체 incident 상태를 집계합니다. 한 source가 CLEAR되어도 다른 활성
  FALL이 있으면 STM32에는 FALL을 유지하고, 마지막 활성 사건이 해제된 때만 FALL_CLEAR를 보냅니다.
- ESP32는 부팅할 때 공식 writer session을 NVS에 한 번 증가·commit하고 그 값을 UART command_epoch로
  사용합니다. READY를 OUTPUT보다 먼저 보냅니다. command_id는 epoch 안에서 1부터 단조 증가하며 0이나
  wrap을 허용하지 않습니다. STM32는 같은 epoch의 `command_id <= last_command_id`를 재실행하지 않고
  DUPLICATE로 응답하며, 새 READY epoch에서만 last_command_id를 0으로 초기화합니다.
- STM32 UART RX ISR은 byte+timestamp를 512칸 고정 ring에 넣고 즉시 RX를 재arm합니다. parser, OUTPUT
  실행, OLED/RGB/audio와 OUTPUT_RESULT 송신은 main service에서 수행합니다. STM32는 별도 task heap,
  공식 receiver, session 승인, replay window나 incident database를 갖지 않습니다.
- BTN1은 Pace Up/green/audio, BTN2는 Pace Down/yellow/audio, BTN3는 STOP/red/audio입니다. BTN4는 로컬
  reset/mute만 하고 UART나 Mesh로 보내지 않습니다. READY 전 로컬 FALL의 빨간 점멸+긴급 부저는 통신
  장애 때 안전을 지키는 유일한 로컬 상태 예외이며, READY 뒤 ESP32에 다시 publish하여 공식 상태와 합칩니다.
- OUTPUT_RESULT는 STM32 hardware 적용 결과 accepted/duplicate/rejected/hardware-error를 ESP32에
  보고합니다. UART 쓰기 성공과 실제 OLED/RGB/audio 성공은 구분하며 host test나 target build만으로
  물리 출력 성공을 선언하지 않습니다.
- ESP32는 부팅할 때 공식 writer session을 NVS에 한 번 증가·commit한 뒤 sequence 0부터 시작합니다.
  이 commit이 실패하면 공식 publish를 fail-closed로 막습니다. STM32의 `HELLO`는 실행 중인 ESP writer의
  session/sequence/state를 바꾸지 않습니다. 이 경계는 Mesh provisioning·key를 지우지 않으며 NVS session을
  0으로 초기화하지 않습니다.
- 공통 코드는 동적 할당·lock·Mesh TTL/암호화/재조립을 수행하지 않습니다. caller가 직렬화하고 Mesh
  스택이 TTL7과 보안을 담당하며 수신 callback에서 응용 재방송하지 않습니다.

## 활성화 경계

- ESP32: `CONFIG_NOSTOS_PROTOCOL_V2=y`, source1~3의 실제 Mesh primary 주소를 설정합니다. provisioned
  primary로 local source를 자동 선택하고 ESP process lifetime마다 session을 NVS에 먼저 한 번
  증가·commit한 뒤 같은 값을 가진 READY command_epoch를 OUTPUT보다 먼저 보냅니다. STM32 HELLO는
  session을 증가시키지 않고 현재 epoch와 활성 snapshot을 다시 받는 resync 경계입니다.
  주소 0/중복/불일치는 송수신을 거부합니다. opcode는 vendor `0x21/0x02E5`, UART1은 TX17/RX18,
  115200/8N1입니다.
- STM32: CMake `-DNOSTOS_PROTOCOL_V2=ON`. boot는 UART를 준비하고 READY가 올 때까지 HELLO를 1초마다
  보냅니다. READY 뒤에는 local producer frame을 TX하고 OUTPUT 명령을 실행할 뿐입니다. 준비 전 raw v1
  fallback이나 자동 Flash는 하지 않습니다.

새 type은 등록표·고정 길이·codec·상태 처리·golden fixture를 함께 추가합니다. 기존 `(version,type)`의
길이·의미를 바꾸지 말고 헤더 의미가 바뀌면 새 version을 사용합니다.

## 검사

```sh
bash firmware/tools/fw check protocol
bash firmware/tools/fw test protocol
```

CMake는 v2 라이브러리를 strict/sanitizer로 컴파일하고 codec·UART·상태·안전 로직 CTest를 실행합니다.
v2 동작 변경은 양쪽 타깃 빌드와 실물 검증까지 통과해야 배포할 수 있습니다.
