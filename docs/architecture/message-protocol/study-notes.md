## 이해했다고 확인한 것

> 메시지는 전달할 내용이고, 프로토콜은 그 내용을 같은 뜻으로 주고받기 위한 약속이다.

그 밖의 단계는 문서가 준비된 상태입니다. 이해 여부를 미리 완료로 표시하지 않습니다.

## 다음에 궁금한 것

**“STM32 코드에서 정지 요청 메시지는 어떻게 만들까?”**

현재 [03. 메시지 번호](03-message-id.md)에 이름과 값의 관계가 있습니다. 버튼에서 ID를 선택하고 함수를 호출하는 코드를 직접 따라가는 추가 학습은 다음에 진행합니다.

## 기록하는 방법

- 한 번에 질문 하나만 추가합니다.
- 설명을 읽고 직접 말해 본 뒤 이해한 내용을 기록합니다.
- 코드 위치·예외·검증 기록은 해당 문서에 연결합니다.
- 실제 구현과 학습용 예시, 실물 시험 결과를 구분합니다.

## 문서 형식

GitHub와 Obsidian에서 같은 파일을 읽도록 일반 Markdown 제목·목록·상대 링크를 사용합니다. 중첩 접기, 위키 링크, 앱 전용 블록은 사용하지 않습니다.

그림은 `mermaid` 코드 블록입니다. 작성 기준은 GitHub 공식 문서의 [상대 링크](https://docs.github.com/en/get-started/writing-on-github/getting-started-with-writing-and-formatting-on-github/basic-writing-and-formatting-syntax#relative-links)와 [Mermaid 그림](https://docs.github.com/en/get-started/writing-on-github/working-with-advanced-formatting/creating-diagrams)입니다.
