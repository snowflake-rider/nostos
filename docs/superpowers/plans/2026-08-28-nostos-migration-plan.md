# Nostos 이관 실행 계획

사용자가 2026-08-28 설계 경로를 승인했다. 별도 writing-plans skill은 로컬에서 찾지 못했으므로 승인된 설계의 완료 기준을 아래 실행 순서로 구체화한다.

1. **원본 동결 기록**: 이관 대상 파일의 SHA-256, 기존 Git HEAD/status/diff 해시를 기록한다. 원본 파일과 Git에는 쓰지 않는다.
2. **Git 이력 연결**: 목적지에서 원본 커밋을 fetch한다. 기존 문서 커밋과 원본 HEAD를 부모로 하는 merge 이관 커밋을 준비한다. 원본 작업 트리의 미커밋 파일도 복사한다.
3. **복사·분류**: 승인된 code/docs 대응표로 복사한다. 라이선스·HAL·음원은 코드에 유지한다. 빌드 캐시, 산출물, 로컬 IDE/에이전트 설정, 실제 비밀정보는 제외한다. 제외 사유를 기록한다.
4. **빌드 경로·이름**: STM32 프로젝트와 ioc를 nostos_stm32, ESP32 통합 프로젝트를 nostos_esp32로 변경한다. 공통 검사 참조 경로와 SDK/프로젝트 절대 경로를 수정한다. 사용자의 후속 지시에 따라 팀 ESP32는 Layer 8을 기준으로 복사하고 공통 codec 참조와 빌드 이름만 맞춘다. 이전 통합본은 legacy에 보존한다.
5. **문서**: 원문을 보존하면서 링크를 새 경로로 옮긴다. 팀원 시작 문서와 루트 메뉴를 작성한다. 과거 기록과 현재 실행 안내를 구분한다.
6. **검사**: 문서 로컬 링크, 소스 보존, 제외 파일, 한 개의 Git root를 검사한다. 프로토콜·STM32·통신 모듈·Layer 호스트 테스트, 지원되는 ASan/UBSan, Swift GPSCore 테스트를 실행한다.
7. **빌드**: 새 경로에서 STM32 Debug/Release, ESP32 통합, 보존한 Layer/예제 ESP-IDF 프로젝트를 빌드한다. 앱은 사용 가능한 로컬 SDK 범위에서 별도 검사하고 결과를 구분한다.
8. **마감**: 각 파일의 최종 해시·수정 이유와 실제 실행 결과를 기록한다. 원본 변경 없음, Git ancestor, staging 내용, 비밀정보·산출물 제외를 확인한다. 검증된 이관 커밋을 지정된 원격 main에 일반 push하고 원격 SHA를 확인한다.

## 변경 한계

센서 기본값, API/메시지 ID, 핀·주변장치, 음원·판정 로직은 변경하지 않는다. 코드 병합에 따른 기능 확장과 센서별 preset은 후속 작업이다. Flash·reset·serial port open·Mesh 설정 변경은 하지 않는다.

## 실패 처리

오래된 문서 링크는 원본 위치 설명 또는 올바른 코드/문서 링크로 고친다. 빌드 실패는 원본의 문제인지 이동에서 생긴 문제인지 분리해 기록한다. 이관을 넘어서는 기능 수정은 수행하지 않는다. 실패나 미실행 대상을 PASS로 적지 않는다.
