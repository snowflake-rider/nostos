# Verified — 실물 검증 기록

검증일: **2026-08-28 (KST)**. 대상: NUCLEO-F411RE + ESP32-S3 D6·76.

이 디렉터리는 이번 실물 시험에서 확인한 사실을 모은다. 설계 목표나 빌드 성공을 하드웨어 전달 성공으로 대신하지 않는다. 문서 작성 시 보드를 재시험하거나 펌웨어를 변경하지 않았다.

## 확인된 결과

| 검증 | 실제 결과 | 판정 범위 |
| --- | --- | --- |
| 버튼 없는 STM32 → D6 UART | `0x13` 송신 10회, 실제 수신 10회 | 정상 송신 구간 **10/10 성공** |
| 버튼 → STM32 → D6 → 76 | 사용자 버튼 누름 3회, STM32 송신 3회, D6 UART 수신 3회, 76 Mesh 수신 3회 | 이번 버튼 시험 **3/3 성공** |
| UART 임시 시험 후 복구 | 원래 STM32 512KB Flash 복구·verify·reset | 임시 주기 송신 펌웨어를 남겨두지 않음 |

확인한 경로는 다음과 같다.

```text
테스트 버튼(D10/PB6)
  → STM32: 정지 요청 0x13
  → PA9/D8 USART1 TX → D6 GPIO18 UART RX
  → D6(0x0005): Bluetooth Mesh 송신
  → 76(0x0003): 같은 source·ID의 Mesh 수신
```

**ESP32 두 대 확인**은 D6의 UART 수신과 76의 Mesh 수신을 뜻한다. 두 대의 원격 Mesh 수신기나 세 노드 Relay를 검증했다는 뜻이 아니다. B6는 이번 버튼 시험 대상에서 제외했다.

## 판정 시 주의

- STM32 `HAL_OK`나 USB 송신 복사본만으로 ESP32 수신 성공을 판단하지 않는다.
- D6의 `MESH_TX ... api=accepted`만으로 상대 수신을 판단하지 않는다. 이번에는 76의 `MESH_RX source=0x0005 id=0x13 result=queued`까지 확인했다.
- UART 단독 시험에서는 재부팅 직후 잡음이 있었다. 정상 송신 10/10과 재부팅 안정성은 별개다.
- 버튼 시험 관찰 구간에서는 누락·추가 중복·UART 오류를 관찰하지 않았다. 장시간 안정성 보장은 아니다.
- 소스·설정·배선이 바뀌면 이 기록은 과거 검증 결과로 남기고, 새 조건으로 다시 시험한다.

현재 소스의 일반 설명은 [Layer 8](../layers/layer-8/README.md)과 [STM32 프로젝트](../legacy-stm32/README.md)를 참고한다. 그 문서의 다른 검증 항목까지 이번 결과로 승계하지 않는다.
