# NOSTOS 테스트 사례

먼저 모의 메시지로 검사합니다. 실제 보드는 나중에 검사합니다.

처리 기준: [MESSAGE_PROCESSING.md](MESSAGE_PROCESSING.md)

## 정상 사례

| ID | 상황 | 예상 결과 |
| --- | --- | --- |
| C01 | 각 메시지 종류를 한 번씩 보낸다 | 수신 측에 같은 종류와 값이 전달된다. |
| C02 | 메시지 두 개를 연속으로 보낸다 | 두 메시지가 같은 순서로 도착한다. |
| C03 | 메시지 하나를 작은 조각으로 나누어 보낸다 | 수신 측이 기다린 뒤 메시지를 완성한다. |
| C04 | 최솟값과 최댓값의 정상 데이터를 보낸다 | 수신 측이 값을 정상적으로 받는다. |

메시지 그룹: 버튼 요청, 후방 상태, 낙상/SOS, 센서 데이터, 상태 확인(HEARTBEAT), ACK.

## 오류 사례

| ID | 상황 | 예상 결과 |
| --- | --- | --- |
| C05 | 길이가 잘못된 메시지를 보낸다 | 메시지가 거부된다. |
| C06 | 버전이 틀리거나 종류를 알 수 없는 메시지를 보낸다 | 메시지가 거부된다. |
| C07 | 프로토콜 v2에서 CRC가 잘못된 메시지를 보낸다 | 메시지가 거부된다. |
| C08 | 프로토콜 v2에서 같은 메시지를 두 번 보낸다 | 같은 동작이 두 번 실행되지 않는다. |
| C09 | 알 수 없는 노드가 메시지를 보낸다 | 메시지가 거부된다. |

## 부하 및 복구 사례

| ID | 상황 | 예상 결과 |
| --- | --- | --- |
| C10 | 메시지 큐를 가득 채운다 | 시스템이 가득 찼다고 알리고 멈추지 않는다. |
| C11 | 일반 큐를 채운 뒤 프로토콜 v2에서 FALL 또는 SOS를 보낸다 | 긴급 메시지가 들어갈 자리가 남아 있다. |
| C12 | Mesh가 준비되지 않았을 때 메시지를 보낸다 | 전송에 성공한 것처럼 처리하지 않는다. |
| C13 | 잘못된 메시지 다음에 정상 메시지를 보낸다 | 정상 메시지가 문제없이 처리된다. |
| C14 | 브리지를 재시작한 뒤 새 메시지를 보낸다 | 브리지가 정상적으로 시작하고 메시지를 처리한다. |

각 결과는 `PASS`, `FAIL`, `BLOCKED` 중 하나로 기록합니다.
